## 1. Alcance y regla de seguridad

Este documento se construyó exclusivamente con el issue de trabajo y estas tres
fuentes autorizadas:

1. `INFORME_Y_TREE_PARA_IA.md`;
2. `material-academico/programa/INF-324.pdf`;
3. `material-academico/planificacion/INF324_BASE_DE_DATOS_S1_S2.pdf`.

`Proyecto final/` está fuera del alcance: no se analiza, no se usa como fuente,
no se modifica y no se incluye en instrucciones de contexto para una IA. La
exclusión también se aplica a árboles, inventarios, búsquedas y estimaciones.

No se copian al portal datos personales o de contacto presentes en documentos
de planificación. Una evaluación o pauta nunca se publica por el solo hecho de
estar disponible como fuente: requiere revisión humana y separación explícita
entre versión de estudiante y versión docente.

## 2. Convenciones del mapa

- **C01–C36:** identificadores editoriales estables; no reemplazan la fecha ni
  el nombre definitivo de una página.
- **S01-A / S01-B:** dos clases presenciales de una misma semana. La distribución
  se deduce de 36 clases en 18 semanas y 72 horas presenciales; no fija días ni
  horarios.
- **U1 / RA1:** Lenguaje de consulta SQL / resultado de aprendizaje 1.
- **U2 / RA2:** Administración de DBMS / resultado de aprendizaje 2.
- **U3 / RA3:** Implementaciones en Bases de Datos / resultado de aprendizaje 3.
- **Asignación aprobada:** unidad y RA respaldados directamente por la duración
  oficial de 7, 7 y 4 semanas.
- **Foco aprobado:** los focos de las sesiones fueron revisados y aprobados
  humanamente; la IA no debe modificarlos sin una nueva revisión.

### Precedencia cuando dos fuentes difieren

1. El issue gobierna alcance, seguridad y criterios de aceptación.
2. F-02 gobierna RA, unidades y ejes académicos oficiales.
3. F-03 complementa la distribución temporal y las actividades; no reemplaza

   no modifica el programa académico.
5. Un conflicto no se resuelve por inferencia de la IA: se crea una decisión
   pendiente con responsable y fecha.

## 7. Flujo reutilizable para trabajo con IA

### Estados editoriales

`pendiente_fuente → borrador_ia → revision_academica → aprobado → publicado`

- `pendiente_fuente`: falta una fuente o decisión; la IA solo registra el vacío.
- `borrador_ia`: texto trazable aún no apto para estudiantes.
- `revision_academica`: un responsable humano contrasta texto, ejemplos y nivel.
- `aprobado`: existe aprobación humana identificable en la rama o pull request.
- `publicado`: pasó controles técnicos y de privacidad.

Una pauta usa el mismo flujo, pero se mantiene en un destino docente no público.

### Procedimiento por cambio

1. **Abrir una unidad pequeña.** Trabajar una decisión, una clase o un lote
   explícito; indicar rama o pull request y criterio de cierre.
2. **Aplicar la lista cerrada de fuentes.** Entregar a la IA este documento, el
   issue y solo las fuentes necesarias de F-01–F-03. No ampliar el contexto por
   búsquedas exploratorias del repositorio.
3. **Hacer control previo.** Excluir rutas fuera de alcance; detectar nombres,
   contactos, credenciales, respuestas y pautas antes de copiar texto.
4. **Registrar trazabilidad.** Para cada cambio académico guardar fuente,
   sección/página, clasificación (`textual`, `derivado`, `pendiente`) y decisión
   humana relacionada. Una deducción debe estar rotulada como tal.
5. **Redactar sin rellenar vacíos.** Si una fuente no fija título, objetivo,
   secuencia, ejemplo o evaluación, crear una entrada P-xx. No producir contenido
   plausible como si fuera oficial.
6. **Verificar el lote.** Ejecutar `python3 scripts/validate-academic-map.py` y
   las validaciones técnicas específicas del cambio. Adjuntar el resultado a la
   revisión.
7. **Solicitar revisión humana.** Es obligatoria para contenido académico,
   actividades, pautas, instrumentos, puntajes y soluciones. Registrar quién
   aprueba, fecha y observaciones, sin publicar datos personales innecesarios.
8. **Publicar con separación.** Comprobar que el artefacto estudiantil no incluya
   pautas, respuestas, contactos ni credenciales. Solo entonces cambiar el estado
   a `publicado`.
