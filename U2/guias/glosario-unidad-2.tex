\section*{Cómo utilizar esta guía}
\addcontentsline{toc}{section}{Cómo utilizar esta guía}
Esta guía reúne los conceptos, instrucciones y objetos trabajados en las seis
presentaciones de la Unidad 2 y en sus cinco guiones SQL. Puede utilizarse de
dos maneras:
\begin{itemize}
\item \textbf{Lectura progresiva:} seguir los bloques en orden, desde la
seguridad y los procedimientos hasta los triggers.
\item \textbf{Consulta rápida:} buscar un término en el índice o en el
glosario final y revisar el ejemplo asociado.
\end{itemize}
\begin{precaucion}[Regla de lectura]
Antes de ejecutar un script identifique si modifica datos, crea un objeto o
controla una transacción. Pruebe en un esquema de laboratorio y compruebe el
estado de la tabla después de cada COMMIT o ROLLBACK.
\end{precaucion}

\section{Seguridad de la información y PL/SQL}
\subsection{Seguridad de la información}
La seguridad se estudia mediante tres propiedades: confidencialidad,
disponibilidad e integridad. En una base de datos se relacionan con usuarios y
controles de acceso, respaldo y recuperación, y diseño con restricciones.
\begin{ideaclave}
La seguridad de la información protege la información dondequiera que esté;
la seguridad informática se limita al medio informático.
\end{ideaclave}
\subsection{PL/SQL y bloque estructurado}
PL/SQL es el lenguaje procedural de Oracle. Un bloque puede incluir DECLARE para
variables, BEGIN para instrucciones, EXCEPTION para errores y END para cerrar.
\begin{lstlisting}
DECLARE
  v_nombre VARCHAR2(50);
BEGIN
  SELECT NOMBRE_USUARIO INTO v_nombre
  FROM CACB_USUARIO WHERE COD_USUARIO = 1;
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    v_nombre := 'SIN REGISTRO';
END;
\end{lstlisting}
\subsection{Procedimiento almacenado}
Un procedimiento compilado y almacenado recibe parámetros y realiza acciones
de mantenimiento. CREATE OR REPLACE permite actualizar su definición.
\begin{lstlisting}
CREATE OR REPLACE PROCEDURE CACB_CARGA_USUARIOS(
  COD_USUARIO_P NUMBER, NOMBRE_USUARIO_P VARCHAR2)
IS
BEGIN
  INSERT INTO CACB_USUARIO(COD_USUARIO, NOMBRE_USUARIO)
  VALUES(COD_USUARIO_P, NOMBRE_USUARIO_P);
END;
\end{lstlisting}
\begin{precaucion}[Diferencia esencial]
Un procedimiento realiza una acción; una función retorna un valor. Ambos pueden
tener variables locales, pero solo la función declara RETURN.
\end{precaucion}
\subsection{Parámetros, tipos y validaciones}
Los parámetros \texttt{IN} reciben información, \texttt{OUT} entregan un valor al
programa que llama y \texttt{IN OUT} permite ambas operaciones. Si no se indica el
modo, el parámetro es \texttt{IN}. Para evitar que una definición quede
desactualizada cuando cambie una columna, el tipo puede tomar como referencia la
tabla mediante \texttt{tabla.columna\%TYPE}.
\begin{sqlexample}[Procedimiento con validación]
CREATE OR REPLACE PROCEDURE CACB_MODIFICA_USUARIO(
  p_codigo CACB_USUARIO.COD_USUARIO%TYPE,
  p_nombre CACB_USUARIO.NOMBRE_USUARIO%TYPE)
IS
BEGIN
  IF p_nombre IS NULL OR TRIM(p_nombre) IS NULL THEN
    RAISE_APPLICATION_ERROR(-20001, 'EL NOMBRE ES OBLIGATORIO');
  END IF;
  UPDATE CACB_USUARIO
     SET NOMBRE_USUARIO = UPPER(TRIM(p_nombre))
   WHERE COD_USUARIO = p_codigo;
  IF SQL\%ROWCOUNT = 0 THEN
    RAISE_APPLICATION_ERROR(-20002, 'USUARIO NO ENCONTRADO');
  END IF;
END;
\end{sqlexample}
La validación debe ocurrir antes del DML cuando sea posible. Después de una
operación se puede revisar \texttt{SQL\%ROWCOUNT} para distinguir una modificación
real de una llamada cuyo código no existe. El procedimiento no decide por sí solo
si la aplicación confirma la transacción; esa decisión debe quedar documentada y
ser coherente con el bloque que lo invoca.

\section{Concurrencia, bloqueos y transacciones}
\subsection{Concurrencia}
La concurrencia ocurre cuando varios usuarios trabajan sobre recursos
compartidos. LOCK TABLE establece un modo de bloqueo para coordinar operaciones.
\syntax{LOCK TABLE nombre_tabla IN ROW EXCLUSIVE MODE}
ROW SHARE permite acceso simultáneo y evita un bloqueo exclusivo de la tabla.
ROW EXCLUSIVE también impide el modo SHARE y se obtiene automáticamente con
INSERT, UPDATE o DELETE. SHARE permite consultas, pero no actualizaciones.
EXCLUSIVE permite consultas y bloquea las demás actividades.
\begin{sqlexample}[Control de concurrencia]
LOCK TABLE CACB_USUARIO IN ROW EXCLUSIVE MODE;
INSERT INTO CACB_USUARIO VALUES (1, 'CARLOS');
COMMIT;
\end{sqlexample}
\subsection{COMMIT, ROLLBACK y SAVEPOINT}
COMMIT confirma los cambios de la transacción. ROLLBACK deshace el trabajo
actual y SAVEPOINT marca un punto al que se puede retroceder. Una consulta no
coloca un bloqueo de tabla y una tabla bloqueada sigue pudiendo consultarse.
Una transacción comienza con el primer DML y termina con \texttt{COMMIT},
\texttt{ROLLBACK} o un DDL que produzca confirmación implícita. Para conservar
varias operaciones como una sola unidad, es preferible que el bloque llamador
controle la confirmación.
\begin{sqlexample}[Punto de recuperación]
BEGIN
  SAVEPOINT antes_de_actualizar;
  UPDATE CACB_USUARIO SET NOMBRE_USUARIO = 'ANA'
   WHERE COD_USUARIO = 2;
  IF SQL\%ROWCOUNT = 0 THEN
    ROLLBACK TO antes_de_actualizar;
  END IF;
  COMMIT;
END;
\end{sqlexample}
\begin{errorcritico}[Transacción y compilación]
No confundas confirmar la transacción con compilar el procedimiento. Son
acciones diferentes y ocurren en momentos distintos.
\end{errorcritico}
\subsection{Excepciones}
Una excepción es un error PL/SQL que puede producirse implícita o explícitamente.
RAISE transfiere el control al manejador. \texttt{RAISE\_APPLICATION\_ERROR} genera un
error propio con códigos entre $-20\,000$ y $-20\,999$.
\begin{lstlisting}
EXCEPTION
  WHEN PROGRAM_ERROR THEN
    RAISE_APPLICATION_ERROR(-6501, 'ERROR INTERNO');
  WHEN OTHERS THEN
    ROLLBACK;
    RAISE_APPLICATION_ERROR(-20010, 'ERROR DE CARGA');
END;
\end{lstlisting}

\subsection{Catálogo de errores}
Oracle informa cada error con un código numérico y un mensaje. En PL/SQL se
pueden capturar excepciones con nombre, consultar el código mediante
\texttt{SQLCODE} y el texto mediante \texttt{SQLERRM}, o convertir una condición
propia en una excepción con \texttt{RAISE\_APPLICATION\_ERROR}. No existe una
lista finita de nombres para todos los errores de Oracle: el catálogo completo
depende del motor y de sus componentes. La siguiente tabla reúne los códigos
que aparecen con mayor frecuencia al trabajar con procedimientos, funciones,
transacciones y triggers.

\begin{longtable}{p{0.22\textwidth} p{0.20\textwidth} p{0.48\textwidth}}
\toprule \textbf{Código o nombre} & \textbf{Categoría} & \textbf{Cuándo ocurre}\\
\midrule
\texttt{NO\_DATA\_FOUND} / ORA-01403 & Predefinida & \texttt{SELECT INTO} no encuentra ninguna fila.\\
\texttt{TOO\_MANY\_ROWS} / ORA-01422 & Predefinida & \texttt{SELECT INTO} devuelve más de una fila.\\
\texttt{DUP\_VAL\_ON\_INDEX} / ORA-00001 & Predefinida & Se repite una clave primaria o una restricción única.\\
\texttt{VALUE\_ERROR} / ORA-06502 & Predefinida & Conversión inválida, valor nulo no permitido o dato demasiado largo.\\
\texttt{ZERO\_DIVIDE} / ORA-01476 & Predefinida & Se intenta dividir por cero.\\
\texttt{INVALID\_NUMBER} / ORA-01722 & Predefinida & Un texto no puede convertirse al tipo numérico esperado.\\
\texttt{CASE\_NOT\_FOUND} / ORA-06592 & Predefinida & Un \texttt{CASE} sin \texttt{ELSE} no encuentra coincidencia.\\
\texttt{CURSOR\_ALREADY\_OPEN} / ORA-06511 & Predefinida & Se abre un cursor que ya estaba abierto.\\
\texttt{INVALID\_CURSOR} / ORA-01001 & Predefinida & Se usa un cursor cerrado, inexistente o no válido.\\
\texttt{PROGRAM\_ERROR} / ORA-06501 & Predefinida & Error interno de ejecución de PL/SQL.\\
\texttt{STORAGE\_ERROR} / ORA-06500 & Predefinida & PL/SQL no puede reservar memoria suficiente.\\
\texttt{LOGIN\_DENIED} / ORA-01017 & Predefinida & Credenciales inválidas al iniciar sesión.\\
\texttt{NO\_PRIVILEGES} / ORA-01031 & Predefinida & El usuario no tiene privilegios para la operación.\\
\texttt{TABLE\_OR\_VIEW\_NOT\_FOUND} / ORA-00942 & SQL nombrada & La tabla o vista no existe o no es visible para el usuario.\\
\texttt{TIMEOUT\_ON\_RESOURCE} / ORA-00051 & SQL nombrada & Se agota el tiempo esperando un recurso bloqueado.\\
\texttt{MUTATING\_TABLE} / ORA-04091 & Trigger & Un trigger por fila consulta o modifica su propia tabla en mutación.\\
\texttt{CUSTOM} / ORA-20xxx & Personalizada & Regla de negocio definida por el equipo mediante \texttt{RAISE\_APPLICATION\_ERROR}.\\
\bottomrule
\end{longtable}

Los nombres predefinidos se pueden capturar directamente en el bloque
\texttt{EXCEPTION}. Los errores que no tienen nombre predefinido se pueden
asociar con \texttt{PRAGMA EXCEPTION\_INIT} o manejar en \texttt{WHEN OTHERS}.
El código de usuario debe estar entre $-20\,000$ y $-20\,999$; el mensaje puede
tener hasta 2.048 caracteres.

\begin{sqlexample}[Estructura básica de una excepción personalizada]
CREATE OR REPLACE PROCEDURE CACB_CARGA_USUARIO(
  COD_USUARIO_P CACB_USUARIO.COD_USUARIO%TYPE,
  NOMBRE_USUARIO_P CACB_USUARIO.NOMBRE_USUARIO%TYPE)
IS
  USUARIO_DUPLICADO EXCEPTION;
  PRAGMA EXCEPTION_INIT(USUARIO_DUPLICADO, -20001);
BEGIN
  IF COD_USUARIO_P IS NULL THEN
    RAISE_APPLICATION_ERROR(-20002, 'EL CÓDIGO ES OBLIGATORIO');
  END IF;

  INSERT INTO CACB_USUARIO(COD_USUARIO, NOMBRE_USUARIO)
  VALUES(COD_USUARIO_P, UPPER(TRIM(NOMBRE_USUARIO_P)));

EXCEPTION
  WHEN DUP_VAL_ON_INDEX THEN
    RAISE USUARIO_DUPLICADO;
  WHEN VALUE_ERROR THEN
    RAISE_APPLICATION_ERROR(-20003, 'FORMATO DE DATO NO VÁLIDO');
  WHEN OTHERS THEN
    ROLLBACK;
    RAISE_APPLICATION_ERROR(
      -20010,
      'ERROR DE CARGA ' || SQLCODE || ': ' || SQLERRM);
END;
\end{sqlexample}

En la plantilla, \texttt{DUP\_VAL\_ON\_INDEX} identifica una clave repetida,
\texttt{VALUE\_ERROR} identifica un dato incompatible y \texttt{WHEN OTHERS}
funciona como último control. Si se relanza un error, conserve su causa y
registre \texttt{SQLCODE} y \texttt{SQLERRM}; no oculte el diagnóstico con un
mensaje genérico.

\begin{sqlexample}[Asociar un código Oracle sin nombre]
DECLARE
  RECURSO_BLOQUEADO EXCEPTION;
  PRAGMA EXCEPTION_INIT(RECURSO_BLOQUEADO, -51);
BEGIN
  LOCK TABLE CACB_USUARIO IN EXCLUSIVE MODE;
EXCEPTION
  WHEN RECURSO_BLOQUEADO THEN
    RAISE_APPLICATION_ERROR(-20020,
      'NO SE PUDO OBTENER EL BLOQUEO: ' || SQLERRM);
END;
\end{sqlexample}

\begin{errorcritico}[Orden recomendado del manejador]
Coloque primero las excepciones específicas y deje \texttt{WHEN OTHERS} al
final. Registre \texttt{SQLCODE} y \texttt{SQLERRM} y relance el error con
\texttt{RAISE} o \texttt{RAISE\_APPLICATION\_ERROR}.
\end{errorcritico}

\section{Funciones PL/SQL}
Una función es un bloque nombrado que devuelve un valor y puede llamarse como
parte de una expresión. SELECT INTO lleva el resultado de una consulta a una
variable. En los ejemplos se captura \texttt{NO\_DATA\_FOUND} cuando no existe el empleado.
\begin{sqlexample}[Función de sueldo]
CREATE OR REPLACE FUNCTION CACB_OBTENER_SUELDO(EMPLOYEE_ID_F NUMBER)
RETURN NUMBER IS
  SUELDO_OBTENIDO NUMBER := 0;
BEGIN
  SELECT SALARY INTO SUELDO_OBTENIDO
  FROM OEHR_EMPLOYEES WHERE EMPLOYEE_ID = EMPLOYEE_ID_F;
  IF SUELDO_OBTENIDO IS NULL THEN SUELDO_OBTENIDO := 0; END IF;
  RETURN SUELDO_OBTENIDO;
EXCEPTION
  WHEN NO_DATA_FOUND THEN RETURN -1;
END;
\end{sqlexample}
\begin{precaucion}[Restricción]
Una función llamada desde SQL no debe ejecutar INSERT, UPDATE o DELETE, ni
llamar a un subprograma que rompa esa restricción.
\end{precaucion}
\subsection{Funciones de transformación y valores nulos}
Las funciones también pueden concentrar reglas repetitivas, como normalizar
nombres o construir un correo institucional. \texttt{SUBSTR} extrae posiciones,
\texttt{UPPER} estandariza mayúsculas y \texttt{NVL} reemplaza un valor nulo. La
regla debe definir qué ocurre cuando el nombre o el apellido tiene menos letras.
\begin{sqlexample}[Construcción de correo]
CREATE OR REPLACE FUNCTION CACB_GENERA_CORREO(
  p_nombre VARCHAR2, p_apellido1 VARCHAR2, p_apellido2 VARCHAR2)
RETURN VARCHAR2 IS
BEGIN
  RETURN LOWER(SUBSTR(TRIM(p_nombre),1,2) ||
               SUBSTR(TRIM(p_apellido1),1,2) || '.' ||
               REPLACE(TRIM(p_apellido2),' ','') || '@testsql.cl');
END;
\end{sqlexample}
Una función que se use en una consulta debe ser determinista respecto de sus
entradas: para resolver duplicados, conviene que el procedimiento de carga
consulte los correos existentes y agregue un sufijo antes de insertar.

\section{Secuencias}
Una secuencia genera enteros únicos para uno o varios usuarios y puede alimentar
una clave primaria. Sus valores son independientes de las tablas y de la
confirmación de la transacción; por eso pueden existir saltos.
\begin{sqlexample}[Creación de la secuencia de usuarios]
CREATE SEQUENCE CACB_PK_USUARIO
  START WITH 1 INCREMENT BY 1
  MINVALUE 1 MAXVALUE 2500
  CACHE 200 NOCYCLE;
\end{sqlexample}
START WITH fija el primer valor; INCREMENT BY define el paso; MINVALUE y
MAXVALUE fijan límites. CYCLE reinicia al alcanzar MAXVALUE y NOCYCLE evita
reutilizar valores. NEXTVAL incrementa y devuelve el siguiente valor; CURRVAL
lee el valor actual de la sesión después de usar NEXTVAL.
\begin{sqlexample}[Uso en un INSERT]
INSERT INTO CACB_USUARIO(COD_USUARIO, NOMBRE_USUARIO)
VALUES(CACB_PK_USUARIO.NEXTVAL, 'CARLOS');
\end{sqlexample}
El valor de una secuencia no se recupera con ROLLBACK: una inserción cancelada
puede dejar un número libre. \texttt{CACHE} mejora el rendimiento, pero puede
producir saltos si la instancia se reinicia. Por eso una secuencia identifica
filas; no sirve para contar cuántos registros existen ni garantiza que no haya
intervalos.

\section{Cursores PL/SQL}
Los cursores manejan el conjunto de registros devuelto por SELECT. El cursor
implícito es gestionado por Oracle para una fila; el explícito se declara para
varias filas o para reutilizar la consulta. La declaración no lleva INTO.
\begin{sqlexample}[Cursor explícito]
DECLARE
  CURSOR c_usuarios IS
    SELECT COD_USUARIO, NOMBRE_USUARIO
    FROM CACB_USUARIO ORDER BY COD_USUARIO;
BEGIN
  FOR r IN c_usuarios LOOP
    DBMS_OUTPUT.PUT_LINE(r.NOMBRE_USUARIO);
  END LOOP;
END;
\end{sqlexample}
\begin{precaucion}[Orden de las filas]
Si el procesamiento depende del orden, incluya ORDER BY en la consulta del
cursor. No coloque INTO en la declaración del cursor.
\end{precaucion}
\subsection{Atributos y cursores parametrizados}
Después de abrir o recorrer un cursor se pueden consultar \texttt{\%FOUND},
\texttt{\%NOTFOUND}, \texttt{\%ROWCOUNT} e \texttt{\%ISOPEN}. Un cursor parametrizado
permite reutilizar la misma consulta para distintos códigos sin concatenar SQL.
\begin{sqlexample}[Cursor con parámetro]
DECLARE
  CURSOR c_usuarios(p_minimo NUMBER) IS
    SELECT COD_USUARIO, NOMBRE_USUARIO
      FROM CACB_USUARIO
     WHERE COD_USUARIO >= p_minimo
     ORDER BY COD_USUARIO;
BEGIN
  FOR r IN c_usuarios(2) LOOP
    DBMS_OUTPUT.PUT_LINE(r.COD_USUARIO || ': ' || r.NOMBRE_USUARIO);
  END LOOP;
END;
\end{sqlexample}
El ciclo \texttt{FOR r IN cursor} abre, obtiene y cierra automáticamente el
cursor. El cursor explícito con \texttt{OPEN}, \texttt{FETCH} y \texttt{CLOSE} es
útil cuando se necesita controlar cada etapa, pero exige cerrar el recurso aun
cuando ocurra una excepción.

\section{Triggers e integridad}
Un trigger es un bloque PL/SQL asociado a una tabla que se dispara por INSERT,
UPDATE o DELETE. Sus componentes son nombre, evento y cuerpo; WHEN es opcional.
FOR EACH ROW hace que se ejecute una vez por cada fila.
\begin{sqlexample}[Cálculo automático del promedio]
CREATE OR REPLACE TRIGGER CACB_PROMEDIO_AUTO
BEFORE INSERT ON CACB_DETALLE_NOTAS
FOR EACH ROW
BEGIN
  :NEW.PROMEDIO := ROUND((:NEW.NOTA1+:NEW.NOTA2+:NEW.NOTA3)/3,1);
END;
\end{sqlexample}
:NEW representa los valores nuevos y :OLD los anteriores. Los triggers sirven
para mantener restricciones de integridad complejas, auditar información y
avisar a otros programas. Un trigger no puede emitir COMMIT, ROLLBACK ni
SAVEPOINT.
Un trigger \texttt{BEFORE} puede corregir o completar \texttt{:NEW}; un trigger
\texttt{AFTER} es apropiado para registrar que la operación ya ocurrió. En un
INSERT solo existe \texttt{:NEW}; en un DELETE solo \texttt{:OLD}; en un UPDATE
están disponibles ambos. Las expresiones con nulos deben tratarse de forma
explícita, porque una suma con una nota nula produce un promedio nulo.
\begin{sqlexample}[Promedio tolerante a valores nulos]
CREATE OR REPLACE TRIGGER CACB_PROMEDIO_AUTO
BEFORE INSERT OR UPDATE OF NOTA1, NOTA2, NOTA3
ON CACB_DETALLE_NOTAS
FOR EACH ROW
BEGIN
  :NEW.PROMEDIO := ROUND((NVL(:NEW.NOTA1,0) +
                          NVL(:NEW.NOTA2,0) +
                          NVL(:NEW.NOTA3,0)) / 3, 1);
END;
\end{sqlexample}
Antes de publicar un trigger, compruebe si debe actuar por fila o por sentencia,
qué eventos lo activan y si puede generar recursión al modificar la misma tabla.
\begin{errorcritico}[Transacción fuera del trigger]
El trigger calcula o valida la fila; el procedimiento o bloque que lo invoca
debe controlar la transacción.
\end{errorcritico}

\section{Ruta de revisión de un script}
Para revisar un guion de la unidad, siga este orden:
\begin{enumerate}
\item Identifique los objetos que crea o reemplaza y verifique que el esquema
      tenga los privilegios necesarios.
\item Compruebe tipos, nombres y restricciones de las tablas antes de compilar
      procedimientos, funciones o triggers.
\item Separe la prueba de compilación de la prueba funcional: consulte los
      errores con \texttt{SHOW ERRORS} y luego ejecute casos válidos y casos
      límite.
\item Observe la transacción: anote dónde se bloquea, dónde se confirma y qué
      excepción provoca un rollback.
\item Valide el resultado con una consulta independiente y deje el esquema de
      laboratorio en un estado conocido.
\end{enumerate}
\begin{precaucion}[Pruebas mínimas]
Incluya al menos un registro válido, un código inexistente, un valor nulo, un
duplicado de clave y una ejecución concurrente cuando el script utilice
secuencias o LOCK TABLE. Estos casos muestran si la regla está implementada o
solo funciona para el ejemplo feliz.
\end{precaucion}

\begin{glossarylist}
\item[COMMIT] Confirma la transacción y materializa sus cambios.
\item[CURRVAL] Devuelve el valor actual de una secuencia en la sesión.
\item[Cursor explícito] Cursor declarado para recorrer varias filas.
\item[EXCEPTION] Sección de un bloque donde se manejan errores.
\item[FOR EACH ROW] Ejecuta un trigger una vez por fila afectada.
\item[Función PL/SQL] Bloque nombrado que devuelve un valor.
\item[LOCK TABLE] Bloquea una tabla en un modo especificado.
\item[NEXTVAL] Incrementa una secuencia y devuelve el nuevo valor.
\item[NO\_DATA\_FOUND] Excepción producida cuando SELECT INTO no encuentra filas.
\item[PL/SQL] Lenguaje procedural incorporado en Oracle.
\item[Procedimiento almacenado] Subprograma compilado que realiza una acción.
\item[RAISE] Transfiere el control al manejador de excepciones.
\item[RAISE\_APPLICATION\_ERROR] Genera un error definido por el usuario.
\item[ROLLBACK] Deshace el trabajo de la transacción actual.
\item[SAVEPOINT] Marca un punto intermedio de recuperación.
\item[Secuencia] Objeto que genera números únicos.
\item[Trigger] Bloque asociado a una tabla que responde a un evento DML.
\item[:NEW / :OLD] Valores nuevo y anterior disponibles en un trigger.
\item[ROW EXCLUSIVE] Modo de bloqueo para operaciones DML por filas.
\item[SELECT INTO] Asigna el resultado de una consulta a una variable.
\end{glossarylist}
